## 动工检查单（每个模块动工前逐条执行）

1. [ ] 读 reference/RuoYi-classic 对应 Controller + ServiceImpl + Mapper XML + **页面模板 HTML + 页面专属 JS**，列出端点总数与 API 清单（方法/路径/参数/返回）写进该模块 spec.md——重点核对页面 JS 实际请求的 URL/方法/参数名
2. [ ] 对照 ry-tp 库实际表结构（经典版官方 SQL），标注用到列；表结构即契约，不做任何 schema 修改
3. [ ] 识别特殊行为：唯一性校验文案、admin 保护、级联（部门 ancestors / 角色菜单关联）、字典联动、权限串（shiro 标签 + JS 变量两处）
4. [ ] 识别数据权限需求（列表带 dataScope 的）与 Excel 导出列定义（@Excel 注解逐字段抄）
5. [ ] 拆 Task 写实该模块 tasks.md（每 Task 可独立验收）、按写实结果细化 checklist.md
6. [ ] 与经典版无法对齐的点登记进 deviations.md

## 环境约束

1. **端口**：本版监听 **8888**（`php think run --port 8888`），与 8080 三版并行，互不影响。
2. **数据隔离**：MySQL **`ry-tp`** 库（本机 Docker 实例，账号见根 AGENTS.local.md；`wencun` 账号若无建库权限改用 docker root，0.0.0 Task 4 处理）+ Redis **db1**（db0 归工作区三版）。表结构 = 经典版官方 SQL 原样导入，不做修改。
3. **测试数据清理**：自己的库自己管——端到端测试数据测试完清理即可，无跨版影响。
4. **调度进程**：10.0.0 的定时任务需另开终端跑 `php think scheduler`（前台常驻），与 web 进程分离。
